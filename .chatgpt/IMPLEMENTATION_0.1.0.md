## 実装の範囲

- .NET 10 の Windows Forms アプリと、OS 非依存のコア状態機械を分離する構成を採用する。
- キー／マウスの低レベルフックを専用スレッドに設置。左Alt単独を抑止し、左Alt + SpaceをAlt + バッククォートのキー入力として送信する。IMEの識別・直接制御は行わない。
- 通常のAltショートカットと最初のAlt + ボタン／ホイール操作は、保留Altと対象イベントをまとめて再送する。
- 修飾なしのバッククォートを解決できない配列では元のAlt + Spaceを維持し、配列ごとに一度案内する。JIS向けに半角／全角を代入しない。
- 長押し・解放順序・停止中の消費済みキーの解放を状態機械で管理する。再開時は保留された物理キー情報を維持する。
- 入力送信が失敗した場合は受理済み押下の解放を試み、一時停止する。全トグルの再試行はしない。
- 部分送信後の回復で既に解放できたAltは二重解放しない。未送信の回復用キー解放のみ保持して再試行する。
- 日本語トレイメニュー、青／灰色アイコン、HKCU Run自動起動、ユーザー／セッション単位の多重起動防止、復帰時の再設定を実装した。
- 停止・再開の表示はフックスレッドの確認応答後に更新する。障害通知と状態通知は順序を維持してUIへ渡す。
- コアの自動テストは依存関係を持たないコンソールランナーで実行する。
- `tool/build-package.ps1` は Windows x64 向けに自己完結発行し、`musha-alt-space-ime-windows-x64.zip` と SHA-256 を作成する。
- GitHub Actions は `release/0.1.0` への push / pull request で復元、コアテスト、自己完結パッケージの作成、workflow artifact の保存を行う。タグや Release の公開は行わない。

## 既知の制約

- ビルドまたはコアの自動テストが成功しても、Windows の低レベルフック、SendInput、通知領域、IME の動作を確認したことにはならない。
- 通常権限のデスクトップアプリを対象とする。管理者アプリ、UAC のセキュアデスクトップ、サインイン画面は対象外である。
- 入力の部分送信失敗時は、二重操作を避けるため元イベントを自動再送しない。停止に至った1回のキー／クリック／ホイール操作が失われる場合がある。回復の送信自体がOSに拒否される場合は、キーを押して離して状態を戻す必要がある。
- 他のキーボードリマップツール、リモートデスクトップ、ゲームなどとの併用は未検証である。
- 本試作はキーボード配列に対して修飾なしでバッククォートを生成できることを要求する。JIS等でその条件を満たさない場合は変換対象外となる。
- マウス操作は最初のボタン／ホイールを通常Alt操作への移行契機とする。移動のみや、ボタンを先に押してからAltを押す操作の互換性は実機検証待ち。
- ATOK、Microsoft 日本語 IME、および各キーボード配列について、実測した版・設定・結果をこの文書に残すまで互換性を表明しない。
