# musha-alt-space-ime 設計書

作成日: 2026-09-22

対象バージョン: 0.1.0

対象ブランチ: `release/0.1.0`

状態: 会話で合意した初期設計。実装およびWindows実機検証は未実施。

## 1. 目的と採用仕様

Windows 11で左Alt + Spaceを使って日本語入力を切り替える、小さな通知領域常駐アプリケーションを作る。

**切り替えの定義は「同じ入力先・同じ状態で、手動のAlt + バッククォート（`）と同じ結果になること」とする。**

アプリケーションはIMEを直接操作せず、左Alt + SpaceをAlt + バッククォート相当のキー入力へ変換する。ATOK・Microsoft IMEの識別、IME別バックエンド、IME状態の問い合わせ・保持は行わない。実際の切り替え結果や変換中の扱いは、Windowsの入力処理と現在選択中のIMEに委ねる。

Alt + バッククォートは、すべてのIME・配列に同じ結果を強制する共通APIではない。対応の判定は手動操作との比較で行う。IME自体をATOKからMicrosoft IMEへ変更したり、入力言語を巡回したりする機能は設けない。

## 2. 対象環境と技術選定

| 項目 | 方針 |
| --- | --- |
| OS | Windows 11専用 |
| 言語・ランタイム | C# / .NET 10 |
| 常駐UI | Windows FormsのApplicationContext、NotifyIcon、ContextMenuStrip |
| キー入力 | Win32 APIのWH_KEYBOARD_LL、SendInput |
| 初期検証IME | ATOK for Windows最新版を優先し、Microsoft日本語IMEも検証 |
| 配布アーキテクチャ | 初期案はx64。ARM64は別途必要性を判断 |
| 実行権限 | 通常ユーザー権限 |

C#は通知領域UIとWin32 API連携の保守性から採用する。C++はサイズ・メモリを最優先する場合の選択肢だが、初期版では保守負担を優先する。Rustも実現可能だがWin32連携の実装が必要となる。Dart / Flutterは実現可能だが、画面がほとんどなく主要処理がWindows固有のため今回は採用しない。

「最新版」は固定の互換性保証を意味しない。検証時点のATOKバージョン・ビルド番号、Windowsビルド、配列と設定を記録する。

## 3. 操作仕様

| 操作 | 動作 |
| --- | --- |
| 左Altを押してからSpaceを押す | Alt + バッククォート相当を1回送信し、元のAlt + Spaceは消費 |
| 左Altを単独で押して離す | 何も送らず、メニューバーにもフォーカスを移さない |
| 左Alt + Tab / F4 / その他のキー | 通常のAltショートカットとして扱う |
| 右Alt | 変更しない。AltGrも変換対象外 |
| Space単独 | 通常の空白入力 |
| 左Alt + Space長押し | Spaceの自動リピートでは追加送信しない |
| 左Altを保持しSpaceを離して押し直す | 新しい押下ごとに1回送信 |
| Ctrl / Shift / Win / 右Altも押されている | 独自変換の対象外。元の組み合わせを維持 |
| Spaceを先に押し、その後左Altを押す | 変換しない |
| Alt + Tabなど通常のAlt操作へ移行済み | 左Altを離すまでIME用の変換へ戻らない |

有効中、左Alt + SpaceによるWindows標準のウィンドウメニューは開かない。一時停止中は通常の動作に戻る。

左右の解放順序に依存せず動作する。Altを先に離した場合でも、消費したSpaceのリピート・解放をアプリへ漏らさない。

## 4. 常駐UI

起動時に通常ウィンドウを表示せず、時計付近の通知領域にアイコンを表示する。タスクバーボタンは作らない。常時表示か折りたたみ領域かはWindowsと利用者の設定に従う。

右クリックメニュー:

```text
☐ ログオン時に起動
  一時停止
─────────────
  終了
```

- 「ログオン時に起動」はチェック可能で、初期値OFF。登録結果を反映し、再起動後も維持する。
- 「一時停止」を押すと「再開」に変わり、アイコンを灰色にする。ツールチップでも状態を示す。
- 一時停止中は左Alt単独を含む通常のWindowsキー動作へ戻す。
- 停止状態は保存しない。次回起動は有効状態とする。
- 「終了」で入力処理・アイコン・その他の資源を解放する。自動起動登録は維持する。
- アイコンは本アプリの有効／停止状態を示し、IMEのON/OFF表示には使わない。
- Explorer再起動時には通知領域アイコンを再登録する。

## 5. 構成

1プロセスで動作し、UIメッセージループと入力フック専用メッセージループを分離する。

| 部品 | 責務 |
| --- | --- |
| ApplicationContext | 起動・終了、部品のライフサイクル管理 |
| TrayController | アイコン、右クリックメニュー、状態表示 |
| KeyboardHook | 入力イベントを受け取り、必要な入力のみ抑止 |
| AltKeyStateMachine | 左Altの保留、単独操作、変換、通常ショートカットを判定 |
| ShortcutSender | 配列を考慮したAlt + バッククォート相当の入力生成・送信 |
| StartupRegistration | ユーザー単位のログオン時起動登録・解除 |
| SingleInstanceGuard | 同一ユーザーセッションの多重起動防止 |

RegisterHotKeyのMOD_ALTは左右を区別しない。また左Alt単独の抑止も必要なため、RegisterHotKeyだけでは実装しない。

入力フック内ではファイル操作、レジストリ操作、UI更新、IME問い合わせ、待機を行わない。必要な仕事を処理順序を維持して引き渡し、速やかに戻る。通常入力を非同期に再送すると順序が入れ替わり得るため、保留入力の送出と後続入力の順序管理を一体として実装する。

## 6. 左Altの状態管理

左Altの押下時点では単独操作かショートカットか判別できないため、最初の押下を保留する。

| 状態 | 入力 | 処理・遷移 |
| --- | --- | --- |
| Idle | 左Alt押下 | 抑止してAltPendingへ |
| AltPending | 左Alt解放 | 抑止してIdleへ。単独Altは無効 |
| AltPending | 条件を満たすSpace押下 | 元入力を消費し、代替ショートカットを送信。ToggleHeldへ |
| AltPending | 別のキー／他の修飾キー | 保留Altと後続入力を順序どおり送出。AltPassthroughへ |
| ToggleHeld | Spaceリピート | 消費のみ |
| ToggleHeld | Space解放 | 解放を消費。左Alt保持中なら次のSpace押下を受け付ける |
| ToggleHeld | 別のキーによる通常Alt操作 | 必要なAlt押下を復元してAltPassthroughへ |
| AltPassthrough | 左Alt解放 | 対応する解放を送出し、通常状態へ |

この表は主要遷移を示す。物理キーの押下集合、消費中のキー集合、Windowsへ送出済みの押下集合を別々に保持し、解放順序や停止途中の整合性を扱う。Idleへの復帰後も未解放の消費済みSpaceがあれば、そのリピートと解放を処理し終えるまで管理を続ける。

- 自分の合成入力はdwExtraInfoなどの識別子で判別し、再変換しない。
- 他ツールが生成した入力は原則として独自変換の対象外とし、不用意に破棄しない。
- フック呼び出し中のGetAsyncKeyStateだけで当該イベント後の状態を判定しない。
- 起動・再開時に既に押されているキーで誤発火させない。必要なキーが解放されてから変換を開始する。
- 一時停止・終了時は新しい変換を止め、合成済みキーの解放と抑止中の入力を整理する。フックを無条件に外すだけでキーを押下状態のまま残さない。
- ロック・スリープ復帰などの境界で古い保留状態を再使用しない。

Alt + クリックの維持にはマウス入力の判別が必要となる。対応範囲と必要最小限のマウスフック導入は試作で確定する。キーボードフックのみで維持できると扱わない。

## 7. Alt + バッククォート相当の送信

元の左Alt押下を保留しているため、Spaceをバッククォートへ置換するだけでは足りない。Windowsへ送出済みの状態を見て、Alt押下・対象キー押下／解放・必要なAlt解放を正しい順序で送る。

基本形はSendInputによる一連のキーイベントである。文字「`」のUnicodeテキスト入力ではなく、ショートカットを構成するキーイベントを生成する。物理Alt保持中の合成Alt解放と、その後の物理Alt解放を区別し、二重解放やAlt単独のメニュー起動を防ぐ。

- US配列のVK_OEM_3を全配列共通として固定しない。
- 入力先の有効なキーボード配列を基に、手動Alt + バッククォート相当となるキーコード／スキャンコードを試作で確定する。
- JIS配列ではバッククォートの文字位置とUS配列のキー位置が異なる。JIS対応を検証なしに保証せず、別の切り替えキーへ黙って置き換えない。
- 入力先が処理待ちの間に変化した場合、古い要求を別ウィンドウへ送らないよう送信直前に再確認する。フォーカス移動との競合は実機試験対象とする。
- SendInputの送信数を確認する。部分送信時は自分が生成した押下状態の回復を行い、全シーケンスを無条件に再送しない。
- 送信成功はIME状態の変更成功と同義ではない。IME状態を推定して通知しない。
- トグル失敗らしく見えても、別方式への自動フォールバックや再トグルは行わない。

以前の候補であったWM_IME_CONTROLによる状態取得・反転、ATOK専用の半角／全角送信、IME別バックエンドは採用しない。

## 8. 自動起動、配置、終了

初期配置案は`%LocalAppData%\Programs\musha-alt-space-ime\`とする。初期配布は.NETランタイム同梱のx64版とし、インストーラー形式や実行ファイル名は実装時に確定する。

自動起動は`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`の本アプリ専用値に、引用符で囲んだ実行ファイルの絶対パスを登録する。

- ON: 登録後に成功を確認してチェックを反映する。
- OFF: 本アプリ専用の値だけ削除する。
- Windowsのスタートアップ設定側で無効にされる可能性があるため、登録有無と実際の起動可否を混同しない。表示と再有効化の詳細は実装時に検証する。
- ログオン時の起動時刻はWindowsの制御に従う。
- アンインストール時は本アプリの自動起動登録を削除する。
- 名前付きMutexで同一ユーザーセッションの多重起動を防止する。
- 終了時は保留入力の整理、フック解除、アイコン削除、Mutex等の解放を行う。

キーストロークや入力文字の履歴を保存しない。診断情報が必要な場合も状態遷移の異常や送信エラー等に限定する。

## 9. 対応範囲と制約

- 通常権限の一般的なデスクトップアプリを初期対象とする。
- SendInputはUIPIの制約を受ける。管理者権限のアプリに対して同じ挙動を保証しない。
- UACのセキュアデスクトップ、サインイン画面は対象外。
- 他のキーボードリマップツール、リモートデスクトップ、ゲームの独自入力処理との併用は別途検証する。
- ATOKとMicrosoft IMEの切り替え方式は共通だが、両者の動作検証は個別に行う。
- UIは当面日本語の3項目とし、設定画面・ショートカット編集・更新確認機能は初期範囲に含めない。
- ライセンスは本設計で新たに決定しない。

## 10. 検証計画と受け入れ条件

### 自動テスト

状態機械のイベント列を検証する。単独Alt抑止、通常ショートカットへの移行、長押し、連続Space、解放順序、他修飾キー、自分の合成入力、停止途中、送信失敗を扱う。重要な不変条件は「不要な文字・メニュー操作を発生させない」「1押下1送信」「自分が送ったキーを押下状態のまま残さない」「通常ショートカットの順序を維持する」である。

### Windows実機試験

| 分類 | 確認内容 |
| --- | --- |
| IME | ATOK最新版、Microsoft日本語IME。正確なバージョンを記録 |
| 入力先 | メモ帳、Edge/Chrome、VS Code、Windows Terminal、Office |
| 基準操作との比較 | 同じ入力先・入力状態で手動Alt + バッククォートと比較 |
| 変換状態 | OFF、ON、未確定文字あり、変換候補表示中、別操作で切り替えた直後 |
| キー | 単独Alt、長押し、連打、解放順序、Alt + Tab/F4、右Alt、他修飾キー |
| 配列 | US、JIS。配列・IME設定・実際の手動操作を記録 |
| ライフサイクル | 停止／再開、終了、ログオン、スリープ／ロック復帰、Explorer再起動、多重起動 |
| 境界 | 入力先変更、部分送信・権限制約、他リマップツールとの併用 |

受け入れ条件:

1. ATOKとMicrosoft IMEで、手動Alt + バッククォートと同じ結果になる。
2. 元のSpace、バッククォート文字、ウィンドウメニュー操作が不要に発生しない。
3. 左Alt単独は無効で、対象外の通常ショートカットは維持される。
4. 停止中は通常操作へ戻り、再開・終了後にキーの押下状態が残らない。
5. トレイの3操作、自動起動のON/OFF、多重起動防止が機能する。
6. 未検証環境を検証済みと表示せず、確認したバージョンと残る制約を記録する。
